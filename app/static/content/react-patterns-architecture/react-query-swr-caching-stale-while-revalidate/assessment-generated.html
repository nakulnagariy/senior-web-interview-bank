React Query / SWR: Caching & Stale-While-Revalidate Assessment

1. What is the "stale-while-revalidate" strategy, and how does it improve UX?
Answer: It shows cached (stale) data immediately while fetching fresh data in the background, so users see data instantly and it updates when new data arrives, reducing perceived latency.
2. How do React Query and SWR handle caching and deduplication?
Answer: Both cache data in memory and deduplicate requests by sharing the same cache and network request for components using the same key.
3. What triggers background revalidation in SWR or React Query?
Answer: Revalidation can be triggered by window focus, network reconnect, interval polling, or manual invalidation.
4. Coding: Show how to use SWR and React Query to fetch user data with caching and SWR.
Answer: 
{`// SWR
import useSWR from 'swr';
const { data, error, isLoading } = useSWR('/api/user', fetcher);

// React Query
import { useQuery } from '@tanstack/react-query';
const { data, error, isLoading } = useQuery(['user', userId], fetchUser);
`}
5. What are the trade-offs of using stale-while-revalidate caching?
Answer: Users may briefly see outdated data, but the UI is always responsive. There is a risk of showing stale data if revalidation fails or is slow.
