SSR vs SSG vs CSR (Next.js) Assessment

1. What is the main difference between SSR, SSG, and CSR in Next.js?
Answer: SSR renders pages on the server at request time, SSG renders pages at build time as static HTML, and CSR renders pages in the browser after JavaScript loads.
2. What are the trade-offs of using SSR for a page?
Answer: SSR provides fresh data and good SEO, but increases server load, can be slower than SSG for static content, and may have higher latency.
3. When is SSG the best choice, and what are its limitations?
Answer: SSG is best for static content that rarely changes (e.g., blogs, docs). Its limitation is that it can't serve dynamic or user-specific data unless using ISR.
4. Why is CSR not ideal for SEO, and when would you still use it?
Answer: CSR renders content in the browser, so search engines may not see the content. It's still useful for highly interactive, app-like pages where SEO is not a priority.

Answer:
