Q1. List and explain the four binding rules for this in JavaScript, with an example for each.
Expected answer signal

  • Default binding: Function called standalone, this is global or undefined in strict mode.
  • Implicit binding: Called as a method, this is the object before the dot.
  • Explicit binding: call, apply, bind set this directly.
  • New binding: Called with new, this is the new instance.

Q2. What is the order of precedence when multiple binding rules could apply?
Expected answer signal

New binding > Explicit binding > Implicit binding > Default binding.

Q3. How do arrow functions handle this binding?
Expected answer signal

Arrow functions do not have their own this; they inherit it from their lexical scope.

Q4. Provide a code sample that demonstrates all four binding rules in action.
Expected answer signal 

{`function foo() { console.log(this.name); }
const obj = { name: 'obj', foo };
const obj2 = { name: 'obj2' };

// Default binding
foo(); // undefined (or 'window' in non-strict mode)

// Implicit binding
obj.foo(); // 'obj'

// Explicit binding
foo.call(obj2); // 'obj2'

// New binding
function Bar() { this.name = 'bar'; }
const b = new Bar();
console.log(b.name); // 'bar'
`}

Q5. What is a common pitfall when using this in callbacks or event handlers, and how can it be avoided?
Expected answer signal

Callbacks lose their intended this binding. Fix with bind, arrow functions, or storing this in a variable.
