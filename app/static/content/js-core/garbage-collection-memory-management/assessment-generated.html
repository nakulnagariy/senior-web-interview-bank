Garbage Collection & Memory Management - Senior Assessment

Topic slug: js-core/garbage-collection-memory-management | Variant seed: 61

Q1. Explain how the mark-and-sweep garbage collection algorithm works in JavaScript.
Expected answer signal

Describes marking all reachable objects, then sweeping and freeing memory for unreachable ones.

Q2. What is a memory leak? Give three common causes in JavaScript applications.
Expected answer signal

Memory leak: memory that is no longer needed but not freed. Causes: global variables, closures holding references, detached DOM nodes, uncleared timers, event listeners.

Q3. How can you detect and debug memory leaks in a web application?
Expected answer signal

Use Chrome DevTools (heap snapshots, allocation instrumentation), monitor memory usage, look for detached DOM nodes, and check for unreleased references.

Q4. Provide a code sample that demonstrates a memory leak and how to fix it.
Expected answer signal 

{`// Memory leak: event listener not removed
function setup() {
  const el = document.getElementById('btn');
  function handler() { /* ... */ }
  el.addEventListener('click', handler);
  // el is removed from DOM, but handler keeps it in memory
}

// Fix:
function setup() {
  const el = document.getElementById('btn');
  function handler() { /* ... */ }
  el.addEventListener('click', handler);
  // On cleanup:
  el.removeEventListener('click', handler);
}
`}

Q5. What is generational garbage collection and why is it used?
Expected answer signal

Divides memory into young and old generations; collects short-lived objects more frequently for efficiency.
