# SCOR RUP CV Alignment Checklist

Use this checklist to align your CV with the role. For each item, add one measurable proof point from your experience.

## A) Headline and Summary

- [ ] Title includes: Senior Frontend Engineer or React Expert (6+ years)
- [ ] Summary mentions: Angular to React migration leadership
- [ ] Summary mentions: Micro-frontend architecture ownership
- [ ] Summary mentions: Azure hosting and CI/CD exposure
- [ ] Summary includes at least two measurable outcomes

Example summary line:

Led phased Angular to React migration across enterprise domains, introducing Module Federation and release guardrails, reducing change failure rate by 30 percent while maintaining delivery velocity.

## B) Must-Have Requirements Mapping

## 1. React expertise (Hooks, optimization, scalable patterns)

- [ ] Evidence of hooks-heavy production architecture
- [ ] Performance optimization examples with metrics
- [ ] Scalable folder or domain architecture ownership

Strong bullet template:

Architected React platform with typed domain boundaries and performance budgets, reducing p95 interaction latency from X ms to Y ms.

## 2. Angular to React migration experience

- [ ] Mentions migration strategy, not just rewrite execution
- [ ] Shows coexistence period handling
- [ ] Includes migration progress metrics

Strong bullet template:

Defined strangler migration strategy from Angular to React, enabling dual-framework operation for N months and migrating X percent of critical routes without release freeze.

## 3. JavaScript and TypeScript mastery

- [ ] TypeScript strict mode usage noted
- [ ] API contract typing and schema validation examples
- [ ] Complex async behavior or runtime issue resolution

## 4. Testing (Jest, React Testing Library)

- [ ] Unit and component testing strategy ownership
- [ ] Test reliability or runtime improvement metrics
- [ ] CI test gating practices included

Strong bullet template:

Introduced RTL-based component testing standards and CI quality gates, improving regression detection and cutting flaky test rate by X percent.

## 5. Micro-frontends (Module Federation or similar)

- [ ] Names tooling used (Module Federation, single-spa)
- [ ] Explains boundary strategy and ownership model
- [ ] Includes deployment independence or reliability outcomes

Strong bullet template:

Designed Module Federation architecture with domain-based remotes and shell contracts, enabling independent deployments across N teams.

## C) Nice-to-Have Requirements Mapping

## 1. Azure environment

- [ ] Lists relevant Azure services used (Static Web Apps, App Service, Front Door, App Insights, Entra ID)
- [ ] Mentions production monitoring and alerting setup
- [ ] Shows secure deployment and environment promotion

## 2. CI/CD and modern toolchain

- [ ] Pipeline ownership is explicit
- [ ] Build tooling is named (Webpack, Vite)
- [ ] Rollout and rollback strategy is shown

## D) Leadership and Soft Skills Proof

- [ ] Stakeholder communication: architecture decisions presented to product and engineering leaders
- [ ] Code review leadership: standards definition and review governance
- [ ] Collaboration: cross-team alignment with platform, QA, and business teams
- [ ] Analytical mindset: trade-off based decisions with measurable outcomes

Strong bullet template:

Led architecture review cadence across product, platform, and domain teams, aligning migration priorities to business critical paths and reducing dependency-driven delays by X percent.

## E) Metrics Checklist (At Least 6 in CV)

- [ ] Performance metric (latency, load time, Web Vitals)
- [ ] Quality metric (defects, failure rate)
- [ ] Delivery metric (lead time, deployment frequency)
- [ ] Reliability metric (incident rate, rollback rate)
- [ ] Migration metric (coverage percent, decommission count)
- [ ] Team impact metric (onboarding speed, review throughput)

## F) CV Red Flags to Remove

- [ ] Generic statements without evidence
- [ ] Listing technologies without outcomes
- [ ] No mention of migration strategy
- [ ] No mention of quality gates and rollback
- [ ] Too much implementation detail, too little impact

## G) One-Page Experience Reframing Template

Use this pattern for each major role:

1. Context:
Enterprise frontend with Angular legacy and React target state.
2. Challenge:
Needed migration while preserving business delivery.
3. Actions:
Strategy, architecture, standards, CI/CD, team leadership.
4. Results:
Quantified impact on reliability, velocity, performance, and migration progress.

## H) Final CV Readiness Score

Score each category from 1 to 5:

- React depth
- Migration leadership
- Micro-frontend architecture
- Azure and CI/CD
- Quality and testing
- Stakeholder influence

Interpretation:

- 24 to 30: Strong fit
- 18 to 23: Good fit with targeted improvements
- 12 to 17: Needs major evidence upgrades
