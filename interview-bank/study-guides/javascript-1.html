Types, primitives and references

“What are the data types in JavaScript? What is the difference between primitives and objects? Is JavaScript pass by value or pass by reference?”

Say this first (30 seconds)

“JavaScript has seven primitive types: string, number, bigint, boolean, undefined, symbol and null. Everything else is an object, including arrays, functions, dates and maps. Primitives are immutable and compared by value. Objects are compared by reference: two objects with the same content are not equal. JavaScript is always pass by value, but the value of an object variable is a reference, so a function can mutate the object it receives, yet reassigning the parameter does not change the caller’s variable. Some people call this ‘call by sharing’.”

Details interviewers probe

  • null vs undefined: undefined is the language’s “no value yet” (uninitialised variable, missing property, missing argument, no return). null is an intentional “no object”. typeof null === "object" is a historic bug kept for compatibility.
  • Checking types: typeof for primitives (safe on undeclared names); Array.isArray() for arrays; instanceof for class instances (breaks across realms such as iframes); Object.prototype.toString.call(x) for the internal tag; x === null explicitly.
  • Wrapper objects: "abc".length works because the primitive is temporarily wrapped in a String object. new String("a") creates a real object; avoid it (it is truthy and not strictly equal to "a").
  • Numbers: one type for integers and floats (IEEE 754 double). Safe integers are up to 253 − 1. See J13.
  • Strings are immutable sequences of UTF-16 code units (J14). Operations return new strings.
  • Symbol: unique and non-colliding; used for property keys, well-known protocols (Symbol.iterator, Symbol.toPrimitive) and hidden metadata. Symbol.for(key) uses a global registry.
  • Copying: assignment copies the reference. Spread and Object.assign make shallow copies; structuredClone makes a deep copy (J9).
  • Equality of objects: {} === {} is false. To compare content you need a deep-equal routine or a stable serialisation.
  • Immutability: const prevents rebinding, not mutation (J3, J9).

Traps

  • Saying “objects are passed by reference”. If that were true, reassigning a parameter would change the caller’s variable. It does not.
  • Saying “there are only 6 primitives” (older answer, before Symbol and BigInt).
  • Calling arrays or functions “not objects”. They are objects with special behaviour.
  • Using typeof x === "object" to test for objects without excluding null.

Likely follow-ups

Why is typeof null “object”?
In the first engine, values were tagged with a type bit and null was the zero pointer, matching the object tag. It was never fixed to avoid breaking the web.
How do you copy an object?
Shallow: spread or Object.assign. Deep: structuredClone (not functions or class prototypes). JSON.parse(JSON.stringify()) loses types and breaks on cycles.
How do you check for an empty object?
Object.keys(o).length === 0 (own enumerable string keys only).
What is a value type in a React context?
Props and state compare with Object.is: new object identity means “changed”, which drives re-renders and effect dependencies.

Type coercion and equality

“What is the difference between == and ===? How does implicit coercion work? What is truthy and falsy?”

Say this first (30 seconds)

“=== compares without converting types. == converts types first using the abstract equality algorithm, which is hard to predict, so I use === by default. The one useful exception is x == null, which matches both null and undefined. Coercion converts values between types: to string, to number or to boolean. Conditions use ToBoolean: the falsy values are false, 0, -0, 0n, empty string, null, undefined and NaN. Everything else is truthy, including "0", [] and {}. Objects are converted to primitives with ToPrimitive, which calls Symbol.toPrimitive, or valueOf and toString.”

Equality family

ComparisonTypes converted?NaN+0 and −0Use
==yesNaN ≠ NaNequalalmost never; x == null is the accepted idiom
===noNaN ≠ NaNequaldefault
Object.isnoNaN is NaNdifferentedge cases; used by React for state and dependency comparison
SameValueZeronoNaN equals NaNequalwhat includes, Map keys and Set use

Conversions in brief

  • ToString: String(x), template literals, + "". null → "null", arrays → joined by commas, plain objects → "[object Object]". Symbols do not convert implicitly (TypeError).
  • ToNumber: Number(x), unary +x. "" → 0, " 12 " → 12, "12px" → NaN, null → 0, undefined → NaN, true → 1. parseInt("12px") → 12, and always pass the radix.
  • ToBoolean: Boolean(x), !!x, conditions, &&, ||, !.
  • + operator: if either operand becomes a string, concatenate; otherwise add as numbers. All other arithmetic operators convert to numbers.
  • Short-circuit operators return operands, not booleans: a || b returns the first truthy, a && b the first falsy, a ?? b the right side only if a is null or undefined.
  • Relational: < converts to primitives, then compares strings lexicographically if both are strings, else numbers. This is why "10" < "9" is true as strings.
const port = config.port ?? 3000;    // keeps 0 and "" as valid values
const port2 = config.port || 3000;   // replaces 0 and "" with 3000 (often a bug)
if (value == null) { /* null or undefined */ }
class Money { valueOf() { return this.cents; } [Symbol.toPrimitive](hint) { return hint === 'string' ? `$${this.cents/100}` : this.cents; } }

Traps

  • “Always use ===” without being able to explain what == does. Describe the rules and the == null exception.
  • Using || for defaults when 0, empty string or false are valid. Use ??.
  • Believing [] is falsy. It is truthy. ([] == false is true through coercion, which is the confusing part.)
  • Forgetting that NaN is the only value not equal to itself; use Number.isNaN (the global isNaN coerces first).

Likely follow-ups

Why is NaN !== NaN?
IEEE 754 defines NaN as unordered with everything, including itself.
Difference between isNaN and Number.isNaN?
The global one converts to number first (isNaN("abc") is true); the Number one only returns true for the actual NaN value.
What does [] + {} teach?
That + calls ToPrimitive on both sides; both become strings, so it concatenates. The point is the mechanism, not memorising results.
When is Object.is useful?
To distinguish +0 and −0 and to treat NaN as equal; it is what React uses to compare state and dependencies.

Scope, hoisting and the temporal dead zone

“Explain scope, the scope chain, hoisting, and the difference between var, let and const. What is the temporal dead zone?”

Say this first (30 seconds)

“Scope decides where a variable is visible. JavaScript uses lexical scope: visibility is fixed by where the code is written, not where it is called. When a name is not found, the engine walks up the chain of enclosing scopes to the global scope. var is function-scoped and hoisted with the value undefined. let and const are block-scoped; they are hoisted too, but they cannot be used before their declaration runs. That gap is the temporal dead zone, and accessing the variable there throws a ReferenceError. const forbids rebinding, not mutation of the object it points to.”

var, let and const

varletconst
Scopefunction (or global)blockblock
Hoistingyes, value undefinedyes, but TDZyes, but TDZ
Redeclare in same scopeallowedSyntaxErrorSyntaxError
Reassignyesyesno (binding is fixed; object contents can change)
Global declaration creates property on globalThisyes (in scripts)nono
In a for loopone binding shared by all iterationsa fresh binding per iteration (closures capture each)fresh binding, cannot be incremented

Default: const, switch to let when you must reassign, avoid var. It signals intent and prevents accidental rebinding.

How it works underneath

  • Each execution context has environment records that map names to values, with a link to the outer environment (the scope chain). A function keeps a reference to the environment where it was created, which is what makes closures possible (J4).
  • Two phases: creation (declarations are registered: var initialised to undefined, functions to their bodies, let/const left uninitialised) and execution (code runs line by line). “Hoisting” is a description of the creation phase, not code being moved.
  • Function declarations in blocks behave differently in sloppy mode (legacy semantics) and strict mode (block-scoped). Avoid them in blocks.
  • Strict mode ("use strict", and automatically in modules and classes): no implicit globals (assigning to an undeclared name throws), this is undefined in plain function calls, duplicate parameters are an error, silent failures become errors.
  • Implicit global: assigning to an undeclared variable in sloppy mode creates a global property. A classic leak source.
  • Shadowing: an inner declaration with the same name hides the outer one. Legal, but lint it (no-shadow).
  • Global scope hygiene: modules have their own top-level scope, so top-level variables do not become globals.
console.log(a);   // undefined   (var is hoisted and initialised)
var a = 1;
// console.log(b); // ReferenceError: Cannot access 'b' before initialization (TDZ)
let b = 2;

const user = { name: 'Ada' };
user.name = 'Bob';   // allowed: the object is mutable
// user = {};        // TypeError: assignment to constant variable

Traps

  • Saying “let and const are not hoisted”. They are hoisted; the TDZ is the proof (an inner let shadows the outer variable for the whole block).
  • Saying “const makes a value immutable”. Use Object.freeze for shallow immutability (J9).
  • Explaining hoisting as code literally moving to the top.
  • Forgetting that function expressions and arrow functions assigned to var are not callable before the assignment.

Likely follow-ups

Why does let in a loop fix the closure-in-loop problem?
Each iteration gets its own binding, so each callback captures its own value.
What is an IIFE for today?
Mostly legacy module isolation. Modules and blocks replace it; still used for async top-level code in scripts.
Is typeof always safe?
For undeclared names yes (returns "undefined"); inside the TDZ it throws.
What is the global object?
globalThis in every environment (window in browsers, global in Node).

Closures

“What is a closure? Give practical uses. What are the downsides?”

Say this first (30 seconds)

“A closure is a function together with a reference to the lexical environment where it was created. It keeps access to the variables of its outer scopes even after the outer function has returned. Note it holds the variables themselves, not copies of their values. I use closures for private state, factories, memoisation, partial application, callbacks and event handlers, and the module pattern. They are also how React hooks work, and the source of stale-closure bugs. The cost is that captured variables stay in memory as long as the function lives, so long-lived closures can leak large objects.”

Practical uses

UseWhy a closure
Private state / encapsulationvariables are unreachable except through returned functions (module pattern, factories; before #private fields)
Function factories and partial applicationconst add = a => b => a + b; configuration baked into the returned function
Memoisation / cachingthe cache lives in the enclosing scope
Callbacks, event handlers, timershandler remembers the data at registration time
Debounce / throttle / oncetimer id or flag kept in the closure
React hookseach render’s functions close over that render’s props and state
Iterators and generators, currying, middleware chainsretain position or next handler

Downsides and pitfalls

  • Memory retention: everything in the captured scope can stay alive. Engines (V8) typically retain only variables that some closure actually references, but variables shared by several closures in one scope, or use of eval, can keep more alive. Large DOM nodes or data captured by long-lived listeners are a classic leak. Remove listeners, clear timers, null large references.
  • Loop with var: all callbacks share one variable. Use let (a new binding per iteration) or an IIFE.
  • Stale closures: in React a callback or effect captures the props and state of its render. With a missing dependency it keeps using old values. Fixes: correct dependency array, functional updates (setCount(c => c + 1)), refs for latest values.
  • Hard to test or debug if overused as hidden state.
  • Performance: creating closures in hot loops allocates; usually irrelevant, relevant in render paths with many children (and for memoised children, a new function each render defeats React.memo).
function once(fn) { let done = false, result; return (...args) => done ? result : (done = true, result = fn(...args)); }
function createStore(initial) {
  let state = initial; const listeners = new Set();           // private, only reachable via the API below
  return { get: () => state, set(next) { state = next; listeners.forEach(l => l(state)); }, subscribe(l) { listeners.add(l); return () => listeners.delete(l); } };
}

Traps

  • Defining a closure as “a function inside a function”. The essential part is access to the outer environment after the outer function returned.
  • Saying closures copy values. They share live variables.
  • Answering only with the counter example. Add a real use: hooks, debounce, private state, a cleanup function.
  • Claiming closures always cause memory leaks. They retain memory only while reachable.

Likely follow-ups

How do closures relate to scope?
Lexical scope defines which variables are visible; a closure is the runtime bundle of function plus environment that keeps that visibility alive.
How would you find a closure-related memory leak?
Heap snapshots in DevTools Memory: compare snapshots, inspect retainers (“Closure” / “Context”) of detached DOM nodes or growing arrays.
Does an arrow function create a closure?
Yes, every function does; arrows also capture this and arguments lexically.
How are closures and private fields different?
Closure privacy is per instance and costs a function copy per instance; #private fields are shared on the prototype chain methods and checked by the engine.

this binding

“How is this determined in JavaScript? How do arrow functions differ? What are call, apply and bind?”

Say this first (30 seconds)

“this is not about where a function is written, it is about how it is called. There are four rules, in order of priority: new creates a fresh object; explicit binding with call, apply or bind sets it; a method call obj.fn() uses obj; otherwise the default is undefined in strict mode and the global object in sloppy mode. Arrow functions have no this of their own: they take it from the enclosing scope at definition time, and it cannot be changed. That is why they are used for callbacks and class fields, and why they are wrong for object methods that need their own this.”

call, apply, bind

Runs now?ArgumentsReturns
fn.call(obj, a, b)yeslistedthe result
fn.apply(obj, [a, b])yesarraythe result
fn.bind(obj, a)nolisted, partial applicationa new bound function

Arrow function differences

  • No own this, arguments, super or new.target; they use the enclosing ones.
  • Cannot be used with new; have no prototype.
  • call, apply and bind cannot change their this (arguments still work).
  • Cannot be generators. Shorter syntax with implicit return.
  • Do not use as object methods or prototype methods when you need this to be the object, and avoid where the caller sets this (some library callbacks).

Where you meet this

  • DOM event handlers: a regular function handler has this equal to the element (currentTarget); arrow handlers do not.
  • Classes: methods are not auto-bound. Passing this.handle as a callback loses this. React class components needed bind in the constructor; hooks removed the issue.
  • Nested functions: an inner regular function does not inherit the outer this (the old const self = this or .bind(this)); arrows do.
  • Strict vs sloppy: modules and classes are strict, so a detached call gives undefined and a clear TypeError instead of silently touching window.
  • Top level: in a module this is undefined; in a CommonJS module it is module.exports; in a classic script it is the global object.

Traps

  • “this is the object the function is defined in.” It is decided by the call, except for arrows.
  • Arrow function as an object method that uses this.
  • Thinking bind twice re-binds. The first bind wins.
  • Forgetting that the default rule differs between strict and sloppy mode.

Likely follow-ups

Implement bind conceptually.
Return a function that calls the original with the fixed this and the partial arguments prepended to the new ones (and handle new on the bound function).
What does new do?
Creates an object whose prototype is F.prototype, calls F with this set to it, and returns it unless F returns another object (J6).
What is globalThis?
A standard way to reach the global object in any environment.
Why do React class components bind handlers?
Because this.handleClick passed as a prop is called without its object, so this is lost.

Prototypes and inheritance

“How does prototypal inheritance work? What is the prototype chain? What does new do? What is the difference between __proto__ and prototype?”

Say this first (30 seconds)

“Every object has an internal link, [[Prototype]], to another object or to null. When I read a property, the engine looks on the object itself, then follows that link up the chain until it finds it or reaches null. That chain is how inheritance works: objects inherit directly from other objects. prototype is a property of constructor functions: it is the object that becomes the [[Prototype]] of instances created with new. __proto__ is the accessor that exposes an object’s actual [[Prototype]]; the modern way is Object.getPrototypeOf and Object.setPrototypeOf. Classes are syntax over this mechanism.”

What new does

  1. Creates a new empty object.
  2. Sets its [[Prototype]] to Constructor.prototype.
  3. Calls the constructor with this bound to the new object.
  4. Returns the new object, unless the constructor returns another object (primitive returns are ignored).
function Person(name) { this.name = name; }
Person.prototype.greet = function () { return `Hi ${this.name}`; };   // shared by all instances (one copy)
const ada = new Person('Ada');

// equivalent without new:
const proto = { greet() { return `Hi ${this.name}`; } };
const bob = Object.create(proto); bob.name = 'Bob';

Object.getPrototypeOf(ada) === Person.prototype;   // true
ada instanceof Person;                              // checks Person.prototype is in ada's chain
Object.hasOwn(ada, 'name');                         // own property check (prefer over hasOwnProperty)
'greet' in ada;                                     // own or inherited

Inheritance patterns

PatternHowNote
Constructor + prototype (ES5)Child.prototype = Object.create(Parent.prototype); Child.prototype.constructor = Child; Parent.call(this, …)verbose, error-prone
Object.create(proto)object-to-object delegation (OLOO)no constructors needed; Object.create(null) makes a dictionary with no prototype
class … extends (ES2015)sets up both the instance chain and the constructor chainpreferred syntax (J7)
Mixins / compositioncopy or compose behaviour (Object.assign(Target.prototype, mixin), factory functions)avoids deep hierarchies

More points

  • Own vs inherited: Object.keys, JSON.stringify, spread see own enumerable properties only; for…in also walks inherited enumerable ones (avoid it for arrays; combine with Object.hasOwn).
  • Memory: methods on the prototype exist once; methods created in the constructor (or class field arrow functions) exist per instance.
  • Built-ins are prototype-based too: arrays inherit from Array.prototype, functions from Function.prototype, all from Object.prototype. Do not modify built-in prototypes (“monkey patching”): it breaks libraries and collides with future standards (a famous case: Array.prototype.flatten renamed to flat because of MooTools).
  • Performance: engines (V8) optimise with hidden classes (shapes) and inline caches; avoid changing an object’s prototype after creation (setPrototypeOf is slow) and avoid very deep chains.
  • Security, prototype pollution: a merge or set-by-path function that accepts keys like __proto__ or constructor.prototype can modify Object.prototype, affecting every object. Mitigate: validate keys, use Object.create(null) or Map, Object.freeze(Object.prototype) in hardened environments, structuredClone, keep libraries updated.

Traps

  • Mixing up prototype (function property) and __proto__ / [[Prototype]] (object link).
  • Saying JavaScript has no inheritance, or that classes make it class-based. It is still prototype-based underneath.
  • Believing assignment to an inherited property changes the prototype. It creates an own property that shadows it.
  • Using __proto__ in new code, or for…in without an own-property check.

Likely follow-ups

What does Object.create(null) give you?
An object with no prototype: no inherited keys like toString, safe as a dictionary (though Map is usually better).
How does instanceof work?
It checks whether Constructor.prototype appears in the object’s prototype chain (customisable with Symbol.hasInstance).
Prototype vs class: when would you still use prototypes directly?
Rarely; for delegation with Object.create, polyfills, and to understand library internals.
What is constructor?
A property on Constructor.prototype pointing back to the function; it is lost if you replace the prototype object without restoring it.

Classes

“Are JavaScript classes real classes? What do extends, super, static and #private do? Composition or inheritance?”

Say this first (30 seconds)

“Classes are syntax over the prototype system, with some real differences: the class body is always strict, the constructor must be called with new, methods are non-enumerable, and classes are not usable before their declaration. extends links both the instance prototype chain and the constructor chain; in a derived constructor I must call super() before touching this. static members belong to the class itself. #private fields are truly private and enforced by the engine, unlike a naming convention. In practice I prefer composition over deep inheritance and plain functions where I do not need identity or state.”

  static get count() { return Account.#count; }
}
class Savings extends Account {
  constructor(owner, rate) { super(owner); this.rate = rate; }      // super() before this
  addInterest() { return this.deposit(this.balance * this.rate); }
}

Composition over inheritance

Deep hierarchies couple subclasses to parent internals (the fragile base class problem), and JavaScript allows only single inheritance. Prefer: small objects or functions combined by composition, mixins (const Serializable = Base => class extends Base {…}) when you need shared behaviour, and dependency injection for collaborators. Use inheritance for real “is-a” relationships with a stable base, such as custom Error types. React moved from class components and inheritance to function components, hooks and composition; the docs explicitly recommend composition.

Traps

  • “Classes were added so JavaScript is object-oriented now.” It is the same prototype model with nicer syntax and a few semantic differences.
  • Using arrow-function class fields everywhere for binding: they create one function per instance and are not on the prototype (hard to mock or override in subclasses).
  • Reading this before super() in a derived constructor (ReferenceError).
  • Assuming #private is the same as a _underscore convention. The former is enforced.

Likely follow-ups

Can you extend built-ins?
Yes, with class MyErr extends Error; modern engines support it correctly; set this.name and use cause.
What is a mixin?
A function that takes a base class and returns a subclass adding behaviour, allowing multiple capabilities without multiple inheritance.
How do private fields differ from WeakMap-based privacy?
Same goal; #private is native, faster and syntax-checked; WeakMap was the pre-2022 workaround.
Abstract classes?
Not in JavaScript; check new.target === Base and throw, or use TypeScript abstract.

Functions in depth

“What are first-class and higher-order functions? Declaration versus expression versus arrow? Rest, spread and default parameters? Currying versus partial application?”

Say this first (30 seconds)

“Functions are first-class: they are objects, so they can be assigned, passed as arguments and returned. A higher-order function takes or returns a function, like map, debounce or a React HOC. Declarations are hoisted with their body; expressions and arrows are not usable before the line that assigns them. Arrows have lexical this and no arguments. Rest collects arguments into an array, spread expands an iterable into arguments or elements. Default parameters are evaluated at call time. Currying turns f(a, b) into f(a)(b); partial application fixes some arguments and returns a function waiting for the rest.”

Ways to define a function

Parameters

  • Default parameters are evaluated at each call, left to right, and can use earlier parameters. They apply for undefined, not null.
  • Rest (...args): a real array, must be last. Replaces arguments (array-like, not in arrows).
  • Spread f(...arr), [...a, ...b], {...o1, ...o2}: expands iterables (objects: own enumerable properties); shallow.
  • Destructuring in parameters gives named options: function f({ a, b = 2 } = {}).
  • f.length counts parameters before the first default or rest; f.name is inferred.
  • Arguments are passed by sharing (J1): mutating an object parameter affects the caller’s object.

const curry = fn => function c(...a) { return a.length >= fn.length ? fn(...a) : (...b) => c(...a, ...b); };
function debounce(fn, ms) { let t; return (...args) => { clearTimeout(t); t = setTimeout(() => fn(...args), ms); }; }

Other function facts

  • Pure functions: same input gives same output, no side effects. Easier to test, memoise and reason about; the basis of Redux reducers and React rendering (J17).
  • Recursion and the call stack: each call adds a frame; deep recursion throws RangeError: Maximum call stack size exceeded. Tail-call optimisation is in the spec but only implemented in Safari verify, so use loops or trampolines for deep recursion.
  • Function objects have properties (name, length, prototype) and methods (call, apply, bind, toString).
  • Getters and generators are functions with special call behaviour (J9, J12).
  • Async functions always return a promise and are covered in Part 2.

Traps

  • Confusing currying with partial application. Currying changes the function’s shape to unary steps; partial application fixes some arguments of the existing shape.
  • Arrow functions as constructors or methods that need this.
  • Expecting default parameters to apply for null.
  • Using arguments in arrows (it refers to the outer function’s).
  • Creating a new function in every render and passing it to a memoised child.

Likely follow-ups

Debounce vs throttle?

Property descriptors, immutability and Proxy

“What is the difference between Object.freeze, seal and preventExtensions? How do you deep copy? What are Proxy and Reflect used for?”

Say this first (30 seconds)

“Every property has attributes: writable, enumerable and configurable, or a getter and setter. Object.preventExtensions stops adding properties; seal also stops removing and reconfiguring; freeze also stops changing values. All three are shallow. For copying, spread and Object.assign are shallow, structuredClone is the standard deep copy, and the JSON round trip loses types. A Proxy wraps an object and intercepts operations like get, set, has and delete through traps; Reflect offers the default behaviour for each trap. Libraries such as Vue 3 and Immer use proxies for reactivity and drafts.”

Property descriptors

  • Data descriptor: value, writable, enumerable, configurable. Accessor descriptor: get, set, enumerable, configurable.
  • Object.defineProperty defaults every missing attribute to false; properties created by assignment default to true.
  • Enumerable controls for…in, Object.keys, spread and JSON. Configurable: false means you cannot delete or redefine it. Class methods are non-enumerable.
  • Inspect with Object.getOwnPropertyDescriptor(s). Object.isFrozen, isSealed, isExtensible test the state.
  • Key order: integer-like keys ascending, then string keys in insertion order, then symbols.

Proxy and Reflect

  get(target, key, receiver) { log.push(['get', key]); return Reflect.get(target, key, receiver); },
  set(target, key, value, receiver) { if (key === 'count' && typeof value !== 'number') throw new TypeError(); return Reflect.set(target, key, value, receiver); },

});
  • Uses: reactivity systems (Vue 3, MobX), draft state (Immer), validation, logging, access control, default values, lazy loading, API clients (api.users.get()), mocking in tests.
  • Limits: slower than direct access; invariants (a non-configurable property must report its real value); a proxy is not equal to its target (proxy !== target), which breaks identity checks; some built-ins with internal slots (Map, Date) need this bound to the real object; cannot be polyfilled for old browsers.
  • Reflect mirrors the proxy traps, returns booleans instead of throwing for some operations, and is the correct way to forward a trap while preserving receiver.
  • Object.defineProperty reactivity (Vue 2) could not detect added properties; Proxy can (this is a classic “why Vue 3 changed” question).

Traps

  • Calling Object.freeze “deep”. It is shallow.
  • Recommending JSON.parse(JSON.stringify()) for deep clone without listing what it breaks.
  • Mutating state in React or Redux and wondering why nothing re-renders.
  • Forgetting that frozen-object writes only throw in strict mode.

When updating an immutable structure, unchanged branches are reused, so equality checks by identity stay cheap and memory is small.

A proxy tracks which properties an effect reads (get) and triggers the effects on set.
How do getters and setters differ from methods?
They look like properties and run code on access; useful for computed values and validation, but hide cost, so keep them cheap.

Map, Set and weak collections

“When would you use Map instead of an object? What are WeakMap, WeakSet and WeakRef for?”

Say this first (30 seconds)

“Map is a key-value collection where keys can be any value, it remembers insertion order, has a size, and is built for frequent additions and removals. A plain object is for fixed records and JSON; it only has string and symbol keys and inherits keys from its prototype. Set stores unique values. WeakMap and WeakSet hold their keys weakly: if nothing else references the key object, it can be garbage collected, so they are used to attach data to objects without causing leaks. They are not iterable and have no size. WeakRef and FinalizationRegistry exist but are non-deterministic, so I avoid relying on them.”

Details

  • Equality: Map and Set use SameValueZero (NaN equals NaN, +0 equals −0). Two different object literals are different keys.
  • Complexity: the spec requires sub-linear access; engines implement hash tables, so get, set, has, delete are O(1) on average.
  • Set operations: union, intersection, difference are available as methods in newer engines ES2025, check support; otherwise filter with has.
  • WeakMap and private data: was the pre-#private way to hide per-instance state; still useful for metadata on objects you do not own.

  • Using an object as a dictionary with user-controlled keys (__proto__ and prototype pollution). Use Map.
  • Expecting WeakMap to be iterable or to show its size.
  • Using Map for data that must be sent as JSON without converting.
  • Promising that FinalizationRegistry callbacks run. They may never run.

Iterators and generators

“What is the iterator protocol? What are generators and what are they useful for? What is an async iterator?”

Say this first (30 seconds)

“An iterable is an object with a [Symbol.iterator]() method that returns an iterator. An iterator has a next() method that returns { value, done }. for…of, spread, destructuring, Array.from, Map and Promise.all all consume this protocol. A generator function, function*, is an easy way to write an iterator: it pauses at each yield and resumes on the next call, so it produces values lazily, and can even receive values back through next(value). Async generators and for await…of do the same for values that arrive over time, like paginated APIs or streams.”

class Range {
  constructor(a, b) { this.a = a; this.b = b; }
  *[Symbol.iterator]() { for (let i = this.a; i <= this.b; i++) yield i; }   // generator method as the iterator
}
[...new Range(1, 4)];                          // [1, 2, 3, 4]

function* ids() { let i = 0; while (true) yield ++i; }   // infinite, lazy

async function* pages(url) {                   // async generator
  let next = url;
  while (next) { const res = await fetch(next); const body = await res.json(); yield* body.items; next = body.next; }
}
for await (const item of pages('/api/items')) { /* process one at a time */ }

Details

  • Early exit: break or return in for…of calls the iterator’s optional return() method, so resources (file handles, streams) can be released. In a generator, try…finally runs on early exit.
  • Lazy: values are computed on demand, so a pipeline of generators processes one item at a time without intermediate arrays. Iterator helpers (map, filter, take on iterators) bring this to built-ins newer, check support.
  • Iterables in the language: arrays, strings (by code point), Map, Set, arguments, typed arrays, NodeList, generators. Plain objects are not iterable.
  • Async iteration: Symbol.asyncIterator; next() returns a promise; ReadableStream is async iterable in modern runtimes check support; Node streams are async iterables.
  • Generators and async/await: async/await is generators plus promises (the old co library); that is the conceptual link to know.
  • Two-way communication through next(value), throw() and return() is what makes redux-saga effects testable.

Traps

  • Saying plain objects are iterable, or spreading an object into an array ([...obj] throws).
  • Forgetting that a generator object is single-use: once done, it stays done.
  • Using an infinite generator with spread or Array.from (never ends).
  • Not mentioning return() for cleanup.

Likely follow-ups

What does yield* do?
Delegates to another iterable or generator, yielding all its values (and returning its result).
How is async/await related to generators?
An async function behaves like a generator driven by a promise runner: each await is a yield that resumes when the promise settles.
Why would you write an iterator instead of returning an array?
Laziness, memory efficiency, infinite or on-demand data, and control over iteration.
for await…of over an array of promises?
It awaits each value in order; compare with Promise.all, which runs them concurrently.

Numbers, dates and JSON

“Why is 0.1 + 0.2 not 0.3? What are BigInt and safe integers? What is wrong with Date? What does JSON.stringify do to unusual values?”

Say this first (30 seconds)

“Numbers are 64-bit IEEE 754 floating point, so many decimal fractions like 0.1 cannot be represented exactly in binary, and tiny errors appear; I compare with a tolerance or work in integer units, for example cents for money. Integers are exact only up to 253 − 1; beyond that I use BigInt, which cannot be mixed with numbers. Date is a millisecond timestamp with a confusing API: zero-based months, mutable, implementation-dependent parsing, and time-zone traps. I store UTC timestamps or ISO strings, format with Intl, use a library or Temporal for date maths, and treat JSON.stringify as lossy: it drops undefined and functions, turns Date into a string and throws on BigInt and cycles.”

Numbers

  • Comparison: Math.abs(a - b) < Number.EPSILON works near 1; scale the tolerance for larger numbers. For display, toFixed(2) returns a string and rounds by the underlying binary value (so 1.005.toFixed(2) gives “1.00”).
  • BigInt: 123n, arbitrary precision integers; cannot mix with Number in arithmetic (TypeError); no Math functions; JSON.stringify throws unless you add toJSON; good for 64-bit ids and cryptography. APIs that return 64-bit ids should send them as strings.
  • Parsing: Number("12px") is NaN; parseInt("12px", 10) is 12 (always pass the radix); parseFloat; Number.isInteger, Number.isSafeInteger, Number.isFinite.
  • Math.round rounds halves toward +∞ (−2.5 → −2); Math.trunc, floor, ceil. Use Intl.NumberFormat for currency and locale output.
  • Random: Math.random is not cryptographically secure; use crypto.getRandomValues or crypto.randomUUID().

Dates

  • Date stores milliseconds since 1970-01-01 UTC. Methods exist in local and UTC variants. Months are zero-based; years from getYear are legacy.
  • Parsing: ISO 8601 strings are reliable. A date-only string ("2025-03-10") is parsed as UTC while a date-time without offset is parsed as local time. Other formats are implementation-dependent. Always include an offset or Z.
  • Mutable: setDate mutates; copy before changing. Adding “one month” or crossing DST is error-prone with raw arithmetic.
  • Time zones: the browser knows only the user’s zone and UTC. Store timestamps in UTC (or ISO with offset) and render in the user’s zone. For named zones use Intl.DateTimeFormat(locale, { timeZone }).
  • Libraries: date-fns (functional), Luxon (zones), Day.js (small); Temporal is the modern replacement (immutable, zones, calendars), shipping progressively check support.
  • Intl: NumberFormat, DateTimeFormat, RelativeTimeFormat, PluralRules, ListFormat, Collator, Segmenter: locale-aware formatting without libraries.

JSON

  • JSON.parse(text, reviver) and JSON.stringify(value, replacer, space) let you transform. JSON.parse throws on invalid input: wrap in try/catch for external data.
  • JSON has no comments, no trailing commas, no undefined, only double-quoted strings. Never use eval to parse it.
  • Large payloads: parse cost is on the main thread; consider streaming, pagination or a worker.

Traps

  • Saying “JavaScript has a bug with decimals”. It is standard binary floating point.
  • Storing money as floats, or using toFixed as a rounding function in calculations.
  • Passing 64-bit database ids through JSON numbers: they lose precision above 253.
  • Parsing local date strings without a time zone and getting a day-off error in some zones.

Integer minor units (cents) or a decimal library, formatted with Intl.NumberFormat using the currency code.
Why does new Date("2025-03-10") show the previous day in some time zones?
It is midnight UTC, which is the previous evening in zones behind UTC when displayed in local time.
What is -0?
A distinct IEEE value; equal to 0 with === but different under Object.is; appears in some rounding and division results.
How would you send large integers to a browser?
As strings (or as BigInt-aware formats) and parse with BigInt() where arithmetic is needed.

Strings, Unicode and regular expressions

“How are strings represented? Why is "😀".length 2? What are regex flags, lookaheads and catastrophic backtracking?”

Say this first (30 seconds)

“Strings are immutable sequences of UTF-16 code units. Characters outside the basic plane, such as emoji, take two code units, so length counts code units, not characters, while for…of and the spread operator iterate code points. What a user sees as one character can still be several code points (a flag, an accented letter in decomposed form), so for user-facing text I use normalize() and Intl.Segmenter. Regular expressions have flags like g, i, m, s, u, y; they support named groups, lookahead and lookbehind. A badly written pattern with nested quantifiers can backtrack exponentially, a ReDoS risk, so I avoid ambiguity and never run untrusted patterns on untrusted input.”

Strings

  • Immutable: methods return new strings. Building large strings by += in loops is optimised by engines (ropes); arrays and join are also fine.
  • Useful methods: includes, startsWith, endsWith, padStart, slice (prefer over substr/substring), replaceAll, at, trim, split, localeCompare, normalize, codePointAt, String.raw.
  • Template literals support interpolation, multi-line strings and tagged templates (tag`a${b}` calls a function with the string parts and values: used by styled-components, GraphQL gql, lit-html, and for safe SQL).
  • Security: never build HTML with string concatenation from user input (XSS); escape or use textContent, framework binding, or DOMPurify.

Regular expressions

FlagMeaningFlagMeaning
gglobal: all matches; makes the regex stateful (lastIndex)s. also matches newlines
iignore caseuUnicode mode (code points, \p{…} properties); v is a newer superset check support
m^ and $ match line boundariesysticky: match only at lastIndex

  • Groups: capturing (…), non-capturing (?:…), named (?<year>\d{4}), backreferences \1 or \k<name>.
  • Assertions: lookahead (?=…), (?!…); lookbehind (?<=…), (?<!…). They match positions without consuming characters.
  • Quantifiers: greedy by default; add ? for lazy (.*?).
  • APIs: test, exec, match, matchAll (iterator of all matches with groups), replace / replaceAll (with a function or $<name>), split, search.
  • Stateful gotcha: a regex with g or y keeps lastIndex between calls, so reusing it with test() can alternate between true and false. Create a new regex or reset lastIndex.
  • ReDoS: patterns like (a+)+$ or (.*a){20} with failing input take exponential time and can freeze a page or a Node server. Mitigate: avoid nested quantifiers and overlapping alternatives, limit input length, use a linear-time engine or timeout (in Node, a worker), test with a ReDoS checker.
  • Do not parse HTML or email fully with regex. Use a parser or the platform (DOMParser, URL, input type=email).
const m = '2025-03-10'.match(/(?<y>\d{4})-(?<m>\d{2})-(?<d>\d{2})/u);   // m.groups.y === '2025'

Traps

  • Truncating or reversing strings by code unit and cutting an emoji in half.
  • Comparing user-entered text with === without normalising, or sorting names with the default sort().
  • Reusing a global regex across inputs.
  • Validating email or URLs with an overly clever regex instead of the platform.

Likely follow-ups

What is a surrogate pair?
Two UTF-16 code units that together encode one code point above U+FFFF.
Difference between match and matchAll?
Without g, match returns the first match with groups; with g it returns only the matched strings. matchAll returns an iterator of full match objects (requires g).
How do you escape user input for a regex?
Replace special characters with a backslash (s.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')); newer engines may add RegExp.escape check support.
How do you detect and fix ReDoS?
Review quantified groups, run a checker (for example safe-regex, recheck), cap input, rewrite without ambiguity.

ES modules versus CommonJS

“What is the difference between ES modules and CommonJS? What are live bindings? How does tree shaking work? How do dynamic import() and top-level await work?”

Say this first (30 seconds)

“CommonJS is the older Node format: require runs synchronously at runtime, can be called anywhere and conditionally, and exports are a plain object whose primitive values are copied. ES modules are the language standard: import and export are static, so the dependency graph is known before any code runs. That enables tree shaking, early errors and asynchronous loading. ESM exports are live bindings: the importer sees updates, but cannot assign to them. ESM is strict mode by default, supports top-level await and dynamic import() for lazy loading. Browsers use ESM natively; Node supports both, and mixing them needs care.”

More points

  • Named vs default exports: named exports give consistent names, better refactoring, autocompletion and tree shaking; default exports allow any local name and make re-export and search harder. Many style guides prefer named exports (exception: framework conventions, such as Next.js pages).
  • Tree shaking removes unused exports during bundling. It needs ESM syntax, side-effect-free modules ("sideEffects": false in package.json or /*#__PURE__*/ annotations), and avoiding barrel files that pull everything in.
  • Dynamic import('./x.js') returns a promise for the module namespace: code splitting, lazy routes (React.lazy), conditional or on-interaction loading. Works in both ESM and CJS.
  • Top-level await: a module can await at top level; importers wait for it. Use sparingly: it delays dependents and can create waterfalls.
  • Circular dependencies: ESM handles them through live bindings, but accessing a binding before it is initialised gives a ReferenceError (TDZ). CJS returns a partially filled exports object. Fix by restructuring (extract shared code), not by ordering imports.
  • Interop in Node: ESM can import CJS (default import is module.exports); require() of ESM was unsupported for a long time and is arriving in newer versions check Node release notes. A package can ship both through the exports map with import and require conditions, with the dual-package hazard (two copies, two instances of state).
  • package.json fields: main (CJS entry), module (bundler hint), exports (modern, encapsulating, conditional), type, sideEffects, files.
  • Browsers: <script type="module"> is deferred, strict, CORS-fetched, evaluated once per URL; import maps map bare specifiers to URLs without a bundler.
  • Module scope vs globals: top-level variables are module-private; singletons are natural (module instance is cached).

Traps

  • “ES modules are just new syntax.” The static structure and live bindings are the semantic difference.
  • Saying require and import are interchangeable in the same file.
  • Barrel files (index.ts re-exporting everything) that defeat tree shaking and slow dev servers.
  • Believing tree shaking works on any code. Side effects and CJS dependencies block it.

How does code splitting work?
The bundler turns each dynamic import() into a separate chunk loaded on demand, with shared chunks extracted.
Why does the module system matter for bundle size?
Static imports allow dead-code elimination; each unused export or library can be dropped.
What is the module singleton pattern?
Because a module is evaluated once and cached, exporting an instance or state gives a shared singleton across importers (be careful with SSR and duplicated packages).

  4. Keep bundles lean: modern output, no unnecessary polyfills, differential loading only when needed.

Traps

  • Using || where ?? is intended, or ?. to hide bugs (it silences errors that should surface).
  • Saying “Babel polyfills everything”. Babel transforms syntax; polyfills come from core-js or similar.
  • Claiming a feature is “ES6” when it is newer. Mention “ES2020+” and verify.
  • Over-destructuring deeply nested objects in function signatures, hurting readability.

Functional programming in JavaScript

“What is functional programming? What are pure functions, immutability and side effects? Why does React favour this style?”

Say this first (30 seconds)

“Functional programming builds programs from functions that take inputs and return outputs without changing anything outside. A pure function always returns the same result for the same arguments and has no side effects. That makes code easy to test, cache and reason about, and safe to run in any order. Immutability means data is not changed in place; updates create new values, so change detection can use cheap identity checks. Functions are composed and passed around. JavaScript is multi-paradigm, so I apply this where it pays: reducers, selectors, transformations, React render logic, and keep side effects at the edges.”

Why it matters in React and Redux

  • Rendering must be pure: the same props and state give the same JSX; React can render twice (Strict Mode), pause, or discard a render (concurrent features). Side effects belong in event handlers and effects.
  • State updates by identity: React and Redux use shallow or identity comparison to detect change, so mutation produces missed updates.
  • Redux reducers are pure (state, action) => newState functions, which enable time travel, logging and testing; Redux Toolkit uses Immer so you can write “mutating” code that is turned into immutable updates.
  • Selectors and memoisation (useMemo, Reselect) rely on purity.
  • Testing pure functions needs no mocks; effects are isolated and mocked at the boundary.

Trade-offs and pragmatism

  • Performance: copying large structures on every update is costly; use structural sharing (Immer, persistent data structures) and avoid deep clones.
  • Readability: heavy point-free or curried code can be unreadable to a team; prefer clear intermediate names.
  • Not everything is pure: UI and I/O are effects by nature. The goal is to isolate them, not remove them.
  • Mixed paradigms: classes for stateful domain objects and error types, functions for transformation and UI, modules for organisation.
  • Errors as values (result objects) versus exceptions: a style choice; be consistent per layer.
// pure: new array, original untouched
const addTodo = (todos, text) => [...todos, { id: crypto.randomUUID(), text, done: false }];
const toggle  = (todos, id) => todos.map(t => t.id === id ? { ...t, done: !t.done } : t);
// impure on purpose: randomUUID and fetch are at the edge of the program, not inside reducers
const pipe = (...fns) => x => fns.reduce((acc, f) => f(acc), x);

Traps

  • Defining FP as “using map and filter”. The core is purity and immutability.
  • Calling a function pure when it reads Date.now(), Math.random() or a mutable module variable.
  • Claiming immutability is free. Explain structural sharing and where copies cost.
  • Treating FP versus OOP as a war; show when each fits.

Likely follow-ups

Is Array.prototype.sort pure?
No, it mutates; copy first or use toSorted.
What is a monad or functor in JavaScript?
A container with map/flatMap: arrays and promises behave like them. Know the idea; do not push the jargon.
How do you keep side effects testable?
Inject dependencies (fetch, clock) and keep logic in pure functions; test effects with integration tests.
What does Immer do?
Lets you write mutations on a draft Proxy and produces an immutable next state with structural sharing.

How to answer JavaScript questions at L4

  • Open with the 30-second answer, then add the mechanism (“why”), then a trade-off or a production angle (a bug you saw, a React consequence).
  • Name the edge cases an interviewer is waiting for: TDZ for hoisting, min-width-style traps have their JavaScript equivalents here: typeof null, NaN, shallow copies, lost this.
  • Do not hedge on facts you know. For version-specific facts say “I would verify that on MDN”.
  • Connect to React and tooling where natural: identity comparison, stale closures, immutability, tree shaking, polyfills.
  • The interview is theoretical: expect “explain”, “compare”, “when would you use” and “what are the trade-offs”, not code puzzles.
